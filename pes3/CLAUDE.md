# CLAUDE.md — Spelling Time (project context for Claude Code)

## Goal
Static games site for Jason's Grade-3 daughter: spelling (weekly `words.txt`), math, coding, fun, and a garden reward. Hosted on GitHub Pages at his domain. Targets: iPad (Safari) + touch Chromebook. **She discourages easily**: no visible scores/timers/streaks/"wrong"/lives; progress is hidden (parent panel only); rewards are positive-only.

## User prefs (Jason)
Java dev + cybersecurity background, learning Python (prefer Python for tooling). macOS primary, **MacPorts not Homebrew**. Power user, AI novice (suggest prompting/context tips). Wants concise answers, inline source URLs, no sycophancy, explicit uncertainty.

## Hard constraints
- Plain HTML/CSS/vanilla JS ES modules. **No build, no deps, no server, no framework.** Keep it that way.
- Weekly workflow = edit `words.txt` -> `git commit/push`. Don't add steps to it.
- `speechSynthesis`/`Audio.play()` must run synchronously inside the tap (iOS). Games speak at round start from the tap that began the round; `open()` in `js/app.js` mounts synchronously.
- On-screen keyboard (avoids iPad autocorrect) + physical keys. Touch targets >= ~44px.
- Spellbound (github.com/benSlaughter/spellbound, MIT per README, no LICENSE file) is a mechanics reference only; games were rewritten, no code copied.

## Contracts
- Game module: `export function mount(root, entries, api)`; `api={home}`; may return a cleanup fn. `mathquiz.js` exports objects `{mount}` (e.g. `mq.maze`).
- `app.js` `SECTIONS=[{title,needsWords?,games:[{icon,id,name,blurb,needsWords?,mod}]}]`. `id` = deep-link slug (lowercase, unique, stable once shared; deeplink_test reads them from app.js and fails, naming the game, if a menu card has no id). Adding a game = new file + one entry (with an `id`). Menu currently 25 cards in 5 sections (smoke/zombie/new_games/baffle/sw tests assert this). Sections: Spelling, Math, 💻 Coding (issue #19: Robot Course, Turtle Draw, Code Studio), Fun, Rewards.
- Deep links (Jason, 2026-10-23): `index.html#<id>` (e.g. `#robot`, case-insensitive) -> `startFromHash()` shows a `.start-gate` card (`▶ Tap to start`); its tap calls `open()` so speech starts inside a tap (iOS). Unknown id -> menu, hash cleared. `open()` sets the hash and `home()` clears it, via `history.replaceState` (no Back entries). `hashchange` re-runs `startFromHash`. The gate is not busy (`inGame=false`), so an update reload may happen there and lands back on the same card. Test reloads that mean "launch the app" must drop the hash (`relaunch()` in sw_test: start_url has none).
- `words.txt`: first `#` line = list title; `word | optional sentence`; dupes ignored; lowercase.
- Spelling games use `rounds(root, entries, api, renderRound, {perRound=10})`; `renderRound({entry,next,root,later,onLeave})`; call `logRound(word, firstTry)` **once** per word. `chooseWords` quietly favours missed words.
- `logRound` also calls `award()` (+1 garden point per finished word, right or not). Math games call `award()` per answered question via `quiz()`. Garden: 4 pts/flower, cap 30 plots, only grows. Keys: `spelling-games.progress.v1` (hidden), `spelling-games.garden.v1`, `spelling-games.mathlevel`. `clearProgress()` must NOT clear the garden.
- Wordal "first try" = solved within 2 guesses. Math, Spot Match, Simon, Memory, Word Search, Baffle don't log progress (Baffle keeps its own stats key).
- Baffle: 5x5, `generate(words)` (greedy embed + simulated annealing, 8 restarts x 4000 iters, 400 ms budget) maximises how many list words are traceable; `findPath(grid, word, start=[])` (start = required leading cells). Targets = list words on the board; any other `inDictionary` word (3+ letters) = bonus; list words always valid. `award()` per new word. No visible count; slots always shown (`.bf-slots[data-w]`, `.done`, hinted `.now`). 💡 Hint blinks (`.bf-tile.blink`) the next cell of the open target that keeps the most of her path (trims the rest), else first open slot; ties prefer the last hinted word; speaks the word when k=0 or the hinted word changes. Look-ahead `.bf-tile.next` = unused neighbours j with `findPath(grid, w, [...path, j])` for some unfound list word w (list only, no dictionary); `.bf-current.word` = path spells one. Mode key `spelling-games.baffle.lookahead` auto|on|off (parent panel); stats `spelling-games.baffle.stats.v1` `{games, words:{w:{solo,helped,free,streak}}}`; rule key `spelling-games.baffle.fluency` `{streak, share}` (default 2 / 0.75, parent-panel selects); fluent = streak>=rule.streak, auto off when >= ceil(share x list) fluent, decided per board. Parent "Erase history" also clears Baffle stats. Break prompt after 8 min / 40 tries / 12 stuck tries. Blocklist lines ending `+` also drop s/es/ed/ing/er/ers forms; others are exact.
- new_games_test: get a round's word with `heard_word()` (last of `__heard`: speech text or recording filename), not `spoken()[-1]`, which misses words that played a recording (`because`).
- Tests route `words.txt` to `tests/fixtures/words.txt` (12 words, "Week of Oct 26") so the weekly list never breaks them.
- Parent panel: 5 taps within 3s on `#title`, or type `parent` on home (not in a game). Nothing visible links to it.
- Audio: `speakWord(entryOrString)` / `speakSentence(entry)` play `audio/<slug>.m4a` / `<slug>.sentence.m4a` if `audio/manifest.json` `{words:[slug],sentences:{slug:text}}` lists it (sentence text must match words.txt), else fall back to speechSynthesis (also on play() failure). slug = lowercase, non-[a-z0-9] runs -> `_`.
- Math levels: add (within 100), t5, t10, div. Kid-gentle copy: "Try again!", never "wrong".
- Praise: `cheer(kind)` in util.js; kind `'spell'` or `opKind(text)` (`add`/`sub`/`mul`/`div` from + − × ÷). General list never mentions spelling. Spelling games pass `'spell'`, math games `opKind(q.text)`, Explorer `'mul'`, Zombie by question type; Baffle/Spot Match use general.

- Word Volcano win: `erupt()` adds `.vo-flow` (cap + 3 clip-path lava rivers pouring into the lake) and `.vo-crater` (30 looping `.vo-blob` arcs + smoke); `.vo-slots` sits above so the word stays readable. Reduced motion hides blobs/smoke.
- Lily Pad River (issue #8; in Fun) replaced the static Number River (removed 2026-10-22 after Jason tested Lily Pad River on the live site on an iPad). Lily Pad River: setup Spelling/Math/Both (key `spelling-games.river.mode`, default both; Spelling hidden if no words) + math level (shared `spelling-games.mathlevel`). 10 questions, 2 lanes x 4 pads: the answer once per lane + 6 different wrong answers (`PER_LANE`), so a wrong tap sinks only that pad; answer glows after 2 misses. Each pad is a `.lp-pad` button inside a `.lp-slot`; only the slot is moved (Web Animations API, not CSS vars in keyframes) and only the button is styled (sunk = opacity + transform scale), because restyling the moving element made iPad Safari stall it (Jason, 2026-10-22). Even spacing so pads never overlap; reduced motion = static wrapped pads. Spelling wrongs = 4 misspellings + `LIST_DECOYS` (2) other list words (`wordWrongs`). `misspellings(word, avoid)` = y/ie/ies traps first, then doubling, vowel swaps, vowel-pair swaps, silent e; drops real `inDictionary` words and list words; tops up with list words for short words (`put`). Spelling q: `logRound` once; math q: `award()`. A Next button (not a timer) precedes each spelling question so iOS speech runs inside a tap.
- Coding engine (`js/code/`, issue #19): program = JSON array of `{op, arg?, body?}` (`repeat` has `arg` + `body`; `forever` has `body`). `forever` yields a `{tick: true}` item each pass (capped by the normal budget; `threads()` runs with `budget: Infinity`). `walk(program, {maxRepeat=20, budget=500})` generator yields `{block, path, n}` (path = indexes into nested bodies) and returns `'capped'` at a limit; budget counts steps AND repeat passes, so repeat 99 of repeat 99 (even empty) stops fast. `runner({program, exec, onStart, onActive, onEnd})`: `play()` from the start, `step()` one at a time (continues the current run), `stop()` -> onEnd('stopped'), `reset()` (program edited; no onEnd). exec returns a truthy reason to end the run ('goal'/'bonk'); onEnd also gets 'end'/'capped'. A tap during a live step's animation is ignored; after stop/reset, play/step wait for the stale animation instead of dropping the tap. `threads({exec(item, ctx, alive), onActive(key, item|null, ctx), onChange})`: `start(key, program, ctx)` (restarts a running key), `stopAll()`, `running(key?)`; cooperative, interleaved at each await; each forever pass awaits a `setTimeout(0)` so an empty/instant forever can't freeze the page; exec returning 'stop' stops all. `chipStrip({ops, onTap, empty})`: `render(program, openPath)`; any block with a `body` (repeat, forever) is a `.code-box` (header chip + body, `.open` = where new blocks go); chips carry `data-path` ("0.1") + `data-i`; `onTap(path, block)`; `setActive/pulse/poof` take a path (poof also a top-level index). Op metadata `{icon, word, say, color, iconClass?, swatch?}`, word/say/swatch may be fn(block). Drag to reorder: pass `onMove(parentPath, from, to)` (+ `canDrag()`, false while running); pointerdown on a chip, becomes a drag after `DRAG_PX` (10 px), ghost `.code-ghost` (position fixed) + drop bar `.code-drop`, nearest sibling decides before/after; siblings = same container only (a box header drags the whole box; no moves into/out of boxes yet). The click ending a drag is skipped by a `dragged` flag that the next pointerdown clears (a time window swallowed quick taps). `.can-drag .code-chip { touch-action: none }` (touching a chip doesn't scroll). Both games use it (Jason 2026-10-23; drag verified on iPad for Word Search/Baffle, not yet for chips). Turn words: `TURNS` (icon + word, never degrees).

On 'bonk'/'end', after `HOME_DELAY_MS` (900 ms) a `.rb-ghost` (faded robot, data-x/y/d) stays where it stopped, `.rb-crumb` arrows (data-x/y = cell left) show the path, and the robot `goHome()`s; they survive edits and clear in onStart (Jason's request, 2026-10-23: she couldn't see the start after a bump). - Code Studio (issue #22, `js/games/studio.js`): ScratchJr-style. - Offline + updates (issue #13; design, measured GitHub Pages headers and the consistency discussion in the issue comments). `sw.js` scope `/pes3/`: cache-first from the newest complete generation `pes3-c1-<ms>` (has `__complete__`); misses are cached and trigger `verifySoon()` (full check 3 s later); byte-range requests answered from cache (Safari audio). Every stored/served response gets `Cache-Control: no-cache` (`keep()`): with Pages' `max-age=600`, Chrome reused fresh in-memory modules on reload and skipped the worker. Page (`js/offline.js`, called from `app.js` after the menu): register, `warm` (performance resource entries + dict + recordings + icons + logo), full `check` on launch, probe on `visibilitychange` and every `home()`; a probe becomes full if the last full check (localStorage `spelling-games.offline.fullcheck`) is > 6 h old; window `error`/`unhandledrejection` -> full check (max 1 per 5 min). Probe = GET `words.txt` (bytes) + HEAD `js/app.js` (ETag vs its own stored ETag; non-`"hex-hex"` -> full). Full round = HEAD app.js (before), per file: text GET + byte compare, `BIG` (`/dict/`, `.m4a`, `.png`) HEAD + size suffix then GET + byte compare if moved; HEAD app.js (after). **Invariant: a generation is used only if all non-BIG files' ETag times are within `WINDOW` (20 s) = one deploy** (`consistent()`; if ETags aren't `hex-hex`, fallback = app.js ETag same before/after the round). Mixed -> no swap, no in-place writes, retry after 3 s and 6 s, then keep the current copy (`result: 'mixed'`). Consistent + no changes -> fresh responses stored in place (new ETags). Changes -> new generation, `promote()`, `broadcast()` `{type:'updated'}` to all windows. `check()` returns `{updated, result, error?}` with result quiet|same|swapped|mixed|offline|error: `offline` only when `navigator.onLine === false`, any other failure = `error` with the message + failing URL (`naming()` wraps each fetch/body read; issue #24); `status()` includes `last` (shown in the parent panel: "no internet" vs "couldn’t finish (<error>)"). A failed check never changes the copy in use; `saveFull()` counts only same/swapped/mixed. Update applies via `location.reload()` only when not busy (`inGame` or `.overlay`); else `reloadIfPending()` in `home()`. Watchdog: inline classic script in `index.html`; if `window.__started` (set by app.js) is not true 10 s after load, or on a script error before start, it posts a full `check` and reloads if `updated` (sessionStorage `pes3.watchdog` blocks a second repair-reload within 60 s). Never compare ETags across files or encodings. Rollback = copy `tools/sw-off.js` over `sw.js` (deletes `pes3-` caches, unregisters, no fetch handler, no reload); never delete `sw.js` (a 404 leaves the old worker running on its stale copy). Existing suites use `service_workers="block"` (their `page.route` fixtures would not reach worker fetches); `sw_test.py` serves a temp copy at `/pes3/` with Pages-style ETags/304/max-age (or content-hash ETags), simulates deploys by re-stamping mtimes, `SLOW` (delayed GETs) for mid-check deploys, `STALE` for a CDN server that missed the purge, `BROKEN` (connection closed, no response) for one failing file; real offline = `ctx.set_offline(True)` (sets `navigator.onLine` in the worker too), server stopped alone = online-but-failing; `hold()` keeps the page in a game so worker broadcasts don't reload it under `evaluate()`.
- Zombie Trail: 6x6 serpentine (0..35), 4 rockets + N zombies, both jump by the 'Jump size' range. Each run writes `review/<timestamp>.m3u8` (gitignored) of files it made. Apple voice redistribution terms unchecked (consider a private repo). Premium voice names unverified.
- GitHub Pages republish delay: 41 s and 36 s measured (#15, #16, 2026-10-22). Pages: ETag `"<hex mtime>-<hex size>"`, `max-age=600`, Fastly, 304 on weak ETags (Jason's curl, same day).
- Offline copy/updates untested in Safari and on a Chromebook (Chromium only). Unverified there: range-served audio from the worker, `navigator.storage.persist()`, whether the iPad Home Screen app keeps storage separate from Safari. Residual risk: on the very first visit modules come from the network with max-age=600, so an update within ~10 min of that first load might reload into a stale in-memory module once; the next launch fixes it. Consistency rests on Pages' undocumented ETag format and on two assumptions from 2 samples: one deploy's files are stamped within ~1 s, deploys are 30+ s apart (`WINDOW` = 20 s). If one deploy's files were ever spread wider than 20 s, updates would stall as 'mixed' (visible in the parent panel). The fallback for other ETag formats (app.js before/after) does not cover non-atomic deploys or CDN servers disagreeing. Icons are upscaled from the 180 px logo (soft).
- Sandbox emoji font lacked some glyphs in screenshots (blank garden cell); likely fine on Apple devices, unchecked.
- Spellbound math "spaced repetition" stats and unlock gating were deliberately not ported.
